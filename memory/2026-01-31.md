- James asked to rebuild the Memex iOS app (React Native/Expo) as native Swift/SwiftUI
- Reason: Share Extension libraries in Expo are unreliable; native is better
- Created repo: github.com/jamesalmeida/memex-swift (private)

- Codex built the full MVP: 44 files, ~2100 lines of Swift
- Key features: Auth, home grid, spaces, item detail, capture, AI chat, settings, Share Extension
- Uses same Supabase backend as the React Native version
- Share Extension uses shared App Group + Keychain for auth
- XcodeGen project.yml for generating .xcodeproj

### Compilation fixes (iterating with James in Xcode):
1. **Signing** — keychain-access-groups used wrong `group.` prefix; fixed to `$(AppIdentifierPrefix)com.jamesalmeida.memex-swift`
2. **Bundle ID** — changed from `com.jamesalmeida.memex` to `com.jamesalmeida.memex-swift` so both apps coexist on device
3. **Config.swift** — gitignored to protect API keys, added Config.swift.example template
4. **supabase-swift package** — XcodeGen didn't link product properly; James added manually in Xcode
5. **OpenAI API types** — MacPaw/OpenAI 0.4.7 changed types significantly:
   - Request: user=`.string()`, assistant=`.textContent()`, system=`.textContent()`
   - Response: `message.content` is just `String?` (NOT an enum)
6. **Supabase update()** — needs `Encodable` structs, not `[String: Any]`; added `SpaceUpdatePayload` and `ItemUpdatePayload`
7. **MetadataService** — functions.invoke API changed; returns decoded type directly
8. **auth.session** — is async in newer Supabase SDK, needs `try? await`
- Both Supabase URL/keys use same backend as React Native app — no backend changes needed
- Different bundle IDs don't affect Supabase auth (email/password); OAuth would need both bundle IDs registered
- Still working through remaining compilation issues as of session end

### Key learnings:
- Codex can't compile Swift (no Xcode in sandbox), so type mismatches are inevitable
- Package API docs on GitHub are the source of truth — fetch actual source when stuck
- XcodeGen package product linking can be flaky; manual Xcode add is more reliable
